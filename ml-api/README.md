# ComplaintGuard FastAPI service

The API loads the frozen Day 9 TF-IDF/Multinomial Naive Bayes model and provides
trusted complaint, staff, customer, and manager workflow endpoints.

## Inference behavior

- `GET /health` reports model readiness without exposing paths.
- `POST /predict` is a stateless English-only diagnostic endpoint. Myanmar and
  mixed input receive `myanmar_not_production_ready`.
- Authenticated `POST /tickets` first creates a durable, redacted customer ticket,
  then runs trusted routing inference. English predictions below the operational
  `0.60` threshold stay unassigned with `routingSource: manual_review`.
- For Myanmar/mixed ticket submissions, the local pinned translator and frozen
  classifier may produce review evidence, but the ticket always remains
  unassigned for manager review because translation quality was not accepted.
- Translation/classification failure leaves a durable recoverable manual-review
  ticket; it never fabricates a route.

Prediction confidence is an uncalibrated per-input model output, not accuracy or
a correctness guarantee. The model's validation-selected threshold was `0.0`;
`0.60` is a later operational review policy.

## Workflow endpoints

- Customer: list/detail, messages, resolved feedback
- Staff: exact-department list/detail, replies, transitions, management requests
- Manager: operational analytics, low-confidence list, department override
- Admin: no administration endpoints

Every operational endpoint verifies a Firebase ID token and active profile.
Customer ownership and staff department scope are rechecked by trusted code;
mutations use Firestore transactions and idempotency actions. The Admin SDK
bypasses rules, so these backend checks are mandatory.

## Privacy and security boundary

Server redaction targets obvious labeled passwords/PINs, account/card values and
long payment-like numbers. It reduces exposure but does not guarantee
anonymization. Operational complaint text remains sensitive. Historical CFPB
data is never stored in Firestore. No retention/deletion workflow, rate limiting,
monitoring, disaster recovery, production rules verification, or independent
security audit is claimed.

## Local setup

The API requires the ignored artifact:

```text
../models/generated/cfpb_department_model_v1.joblib
SHA-256 bafc086fe5b11bdcc5cbc4f04f3f3f222de8cbad27fe66d62a6685cc30f953d5
```

It is never regenerated by startup or final verification.

```powershell
Set-Location D:\ComplaintGuard\ml-api
..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Live Firebase requires Application Default Credentials and an explicit CORS
allowlist. The verified operating mode instead uses both Firebase emulators and
the isolated `demo-complaintguard` project as documented in
`../docs/demo_guide.md`.

## Tests

..\.venv\Scripts\python.exe -m pytest tests -p no:cacheprovider
